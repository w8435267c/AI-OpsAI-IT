# ADR-0001：知识内容受众 Selector 权限语义

- 状态：已采纳（第 8B 步实现，第 8D 步边界修复）
- 日期：2026-09-06
- 决策人：产品 / 开发（已由用户确认）
- 相关代码：`apps/knowledge/selectors.py`、`apps/knowledge/models.py`、
  `config/settings/base.py`（`KNOWLEDGE_IT_USER_GROUP_ID`）

## 背景

V1.1A 将“系统操作权限”与“内容受众范围”拆为两类（PRD 第 4.2 节）。第 8 步要
实现“内容受众权限选择器”（拒绝优先），决定当前用户可见哪些已发布文章。本 ADR
固化以下已确认的判定语义，作为后续搜索、列表、详情、附件等所有员工阅读路径的
唯一依据。

## 决策

### 1. 系统操作权限与内容受众分离

- Django `Group` / `Permission` 只决定“能做什么”（操作权限）。
- `accounts.UserGroup` 只决定“能看到哪些知识”（内容受众）。
- `is_staff`、`is_superuser`、编辑员、审核员、知识管理员、作者或空间负责人，
  **均不**自动绕过员工阅读路径的受众检查。
- 后续管理、审核入口另行实现独立的管理权限契约，不复用本 Selector。

### 2. 文章策略决定允许范围

允许范围只由 `Article.audience_policy` 决定：

| 策略 | 允许范围 |
| --- | --- |
| `all_employees` | 所有满足账号门槛的用户 |
| `it_only` | 满足账号门槛且属于绑定 IT 内容用户组的用户 |
| `restricted` | 命中显式 allow 的指定部门 / 内容用户组 / 用户 |

- `restricted` 没有有效 allow 时，**无人可见**（包括没有规则和只有 deny）。
- 不根据“是否存在 allow 记录”切换策略或触发回退。
- 不因为增加一条 allow 而缩小全员文章范围。
- **未识别的策略不得放行**（读取侧按失败关闭处理）。

### 3. 拒绝优先

- 任一匹配的 `department` / `user_group` / `user` deny 覆盖允许范围。
- 对 `all_employees`、`it_only`、`restricted` 一致生效。
- 保留现有数据库约束：`all_employees`、`it_only` 类型不能配置 deny。

### 4. 空间默认策略

- `KnowledgeSpace.default_audience_policy` 仅供后续新建文章时赋初值。
- 阅读查询**不使用**空间默认策略进行运行时回退。
- 修改空间默认值不改变既有文章的查询结果。
- 本步不提前实现创建服务。

### 5. 部门与成员关系

- 多部门取并集，不只看主部门。
- **仅精确匹配**指定部门，不包含父部门或子孙部门。
- 关系 `effective_at` 为空或 `<= now` 时生效。
- `expired_at` 为空或 `> now` 时有效；到点立即失效。
- 停用部门、停用内容用户组不参与成员命中判断，该规则同时用于 allow 和 deny。
- 关系删除或调岗后按当前数据库关系判断。
- 不在本步增加跨请求权限缓存。

### 6. 内容状态与时间

- 空间必须启用（`space.is_active=True`）。
- 文章必须 `active`。
- `effective_at` 为空或 `<= now`。
- 必须存在 `current_published_version`，状态为 `published`，且确实属于本文章。
- 新版本待审不影响读取旧的当前发布版本。
- `offline`、`archived`、没有发布版本或发布指针异常，均排除。
- 分类停用仅影响后续导航，不单独隐藏文章。
- `review_due_at` 逾期不自动隐藏；提示或下架策略留待后续实现。
- `space_type` 不作为猜测 IT 身份或绕过文章策略的依据。

## “仅 IT”身份的最小实现

采用现有 `accounts.UserGroup`，通过服务端配置 `KNOWLEDGE_IT_USER_GROUP_ID`
绑定其主键：

- 缺省未配置（`None`）；环境变量入口与 Selector 共用 `parse_it_group_id`。
- 仅接受正整数，或长度 1～19 的 ASCII 十进制字符串（不接受空白、符号、浮点、布尔值）。
  范围为 `1..9223372036854775807`，对应现有 `UserGroup.BigAutoField`；超长输入在转换前拒绝。
  非法值返回 None，查询前再次校验，兼容其他设置模块直接覆盖配置；不吞掉数据库故障。
- 只用于定位一个明确的内容用户组，不按显示名称匹配。
- 不猜测部门名、角色名，不依赖 `is_staff` / `is_superuser`。
- 用户组必须存在且启用，用户必须是其成员。
- 配置缺失、无效或组不存在 / 停用时，不授予 `it_only` 阅读权限，且不导致
  普通文章列表整体抛异常或崩溃。
- 不硬编码开发库主键，不自动创建组或更改成员。
- 不增加 `User.is_it_staff` 字段，不扩大到通讯录同步。
- 该绑定属于权限配置，需由部署管理者按实际权限边界设置。

## 受众写入一致性校验

- `restricted`：允许 `department` / `user_group` / `user` allow。
- `all_employees`：允许同类型 `all_employees` allow 作为可选冗余表达；不需要它才能全员可见。
- `it_only`：允许同类型 `it_only` allow 作为可选冗余表达；不需要它才能判定 IT 可见。
- 与文章策略不一致的 allow 组合在模型 `clean()` 层拒绝，给出中文错误。
- 三种策略均允许合法的 `department` / `user_group` / `user` deny。
- 修改文章策略时（`Article.clean()`）检查既有规则，最终状态一致才放行。
- Article Admin 新增仍关闭。编辑页使用受众 Inline，查看、新增、修改、删除分别遵守
  现有 `ArticleAudience` 模型权限；文章修改权不隐含受众权限，四个系统角色权限集合不变。
- 联合父表单仅在实例级服务器上下文中延后旧受众比较，不关闭其他模型 clean；
  FormSet 校验未变化、修改、新增、删除后的完整最终集合，检查形状、策略和条件唯一性。
  不完整、重复主键或越权表单拒绝；HTTP 字段不能启用延后校验。
- 受众是当前可维护授权关系，架构 ART-008 已约定原子替换；明确删除关系仍要求
  `delete_articleaudience`，不删除文章、版本、审核历史，不给既有角色补充 delete 权限。
- 删除先于修改和新增保存，整个 Admin POST 使用 Django Admin 的数据库事务；失败整体回滚。
  独立 ArticleAudience Admin 保持完整模型校验，不使用联合表单上下文。
- 不自动删除、转换或修复已有受众数据；不恢复 Article Admin 新增权限，不放宽第 7 步边界。

## 实现边界与限制

- `ArticleAudience.clean()` 与 `Article.clean()` 属**模型层校验**，只在
  `full_clean()`（含 Admin ModelForm）路径被调用；`save()` / `objects.create()`
  默认不自动调用 `full_clean()`，因此绕过表单的直接写入不受该校验保护。
- 该策略一致性是跨表规则，**不是**数据库 `CheckConstraint`，无法在数据库层兜底；
  读取侧始终按文章策略计算允许范围，不一致的 allow 不扩大或改变范围，合法 deny
  仍生效，以此保证未授权内容不被泄露。
- 本步不实现发布服务、创建服务、管理权限 Selector 或 HTTP 端点；未来视图必须对
  无权限文章的标题、摘要、数量或响应差异做统一处理，避免泄露存在性。

## base 查询契约（第 8D 步）

- base 是未切片的 Article QuerySet，可包含普通条件与一对多关联过滤。
  使用主键子查询保留范围，外层一篇文章一行，不进行 Python 物化去重。
- 支持普通字段、明确的关联字段路径及升降序、多字段排序、reverse；相同排序值以文章
  pk 稳定排序。一对多排序取 base 按完整排序元组排出的首行作为该文章排序值。
  例如用户名称升序取首个名称，降序取最后名称。select_related/prefetch_related 保留。
- 返回结果支持继续普通字段过滤、排序、count 与分页；权限过滤和去重必须先于分页。
  会引入一对多连接的过滤或排序应放入 base，再调用 Selector；返回后自行连接一对多表
  会重新引入重复，这是 Django QuerySet 的行为，不属于已完成过滤的结果契约。
- 显式拒绝 values 投影、预先切片、集合运算、注解/聚合、extra SQL、行锁、distinct(fields)、
  延迟字段、随机与表达式排序。有关联默认排序的关系名称须写成明确的末级字段路径，
  如 space__name；不静默替换其排序含义。普通 distinct() 支持。
- 未保存 User（包括手工指定已有 pk）按 `_state.adding` 拒绝；不把该内部调用边界
  表述为已证实的 HTTP 漏洞。

## 字段注释迁移（第 8D 步）

空间默认策略仅供新建文章赋初值，读取不回退，修改默认值不改变已有文章。
新增 0003 AlterField 仅同步 db_comment，不修改历史迁移、不更新业务数据。
SQLite 隔离验证不代表 PostgreSQL 注释已核验或持久库已应用迁移。

## 影响

- 员工阅读路径（未来列表 / 详情 / 搜索 / 附件）必须以本 Selector 的判定结果为唯一真相。
- 部署需在正式环境配置 `KNOWLEDGE_IT_USER_GROUP_ID`，否则 `it_only` 文章无人可见。
- 撤销代码不会自动调整用户组成员、配置或数据库状态；权限配置需单独管理。
