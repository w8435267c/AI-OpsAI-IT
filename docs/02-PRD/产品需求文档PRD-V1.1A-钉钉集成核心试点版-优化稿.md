# 1. 文档概述

## 1.1 编写目的

本文档用于明确 OpsAI-IT 故障问答知识库 V1.1A 的产品目标、功能边界、钉钉集成方式、数据与权限规则、非功能要求和验收标准，作为产品设计、技术设计、开发、测试、上线及后续迭代的共同依据。

## 1.2 产品定义

| 一句话定义  面向公司内部员工的 IT 运维知识库：员工在钉钉内直接进入，通过搜索和分类快速解决常见 IT 问题；若知识无法解决，则无缝跳转至现有钉钉 IT 服务表单。 |
| --- |

平台是独立部署的响应式 Web 系统。钉钉负责统一入口、员工身份、应用可见范围和消息触达；知识内容、搜索、权限、审核、统计与后续扩展能力由知识库平台自身负责。

## 1.3 适用对象

产品负责人、IT 运维负责人和知识库运营人员。

前端、后端、测试、运维、安全和钉钉应用管理员。

参与知识编写、审核、发布和使用的内部员工。

## 1.4 约束与假设

| 类型 | 说明 |
| --- | --- |
| 组织约束 | 平台仅面向公司内部员工；钉钉组织身份是默认身份来源。 |
| 建设约束 | 第一期以知识库为核心，不同步建设完整 ITSM、资产管理或权限治理平台。 |
| 部署假设 | 公司可提供 HTTPS 域名、服务器或云资源、数据库、备份与网络访问条件。 |
| 集成假设 | 公司拥有钉钉企业内部应用的创建、配置、权限申请和发布权限。 |
| 内容假设 | IT 团队可持续提供、审核和维护首批高频知识内容。 |

# 2. 项目背景与产品定位

## 2.1 现状与痛点

常见故障被重复咨询，IT 人员大量时间消耗在相同问题的重复解答上。

知识分散在个人经验、聊天记录、临时文档和不同工具中，员工难以找到可信答案。

故障处理步骤缺少统一模板、版本和审核，存在内容过期、操作风险和口径不一致。

独立网站若要求员工记住网址和账号，会增加使用门槛；手机端阅读和现场操作也不方便。

知识未解决时，员工需要再次寻找 OA 或服务表单，问题描述重复填写，服务链路割裂。

IT 内部 SOP、运维案例与普通员工知识未区分可见范围，存在信息暴露风险。

## 2.2 产品机会

钉钉已经是员工日常办公入口。将知识库注册为企业内部 H5 微应用，可把“找入口、登录、确认身份”三步压缩为一次点击；同时保留独立 Web 系统的自主数据管理、搜索优化与模块扩展能力。

## 2.3 产品定位

| 维度 | 定位 |
| --- | --- |
| 目标用户 | 公司内部员工；知识编辑、审核与管理人员。 |
| 核心价值 | 让员工先自助解决高频 IT 问题，让 IT 经验沉淀为可复用、可审核、可追踪的知识。 |
| 主要入口 | 钉钉工作台中的企业内部 H5 微应用；PC 与移动端均可使用。 |
| 身份方式 | 钉钉端内免登为主，后台基于钉钉身份完成用户映射与会话创建。 |
| 服务闭环 | 知识无法解决时跳转到现有钉钉 IT 服务表单或 OA 审批。 |
| 扩展方向 | AI 问答、完整 ITSM、资产、账号权限、软件资源等后续模块。 |

## 2.4 产品原则

| 原则 | 要求 |
| --- | --- |
| 用户视角 | 采用“我的电脑坏了、我要安装软件、我连不上网络”等用户语言，减少内部专业术语。 |
| 搜索优先 | 首页第一视觉焦点是搜索；分类导航用于补充探索。 |
| 统一入口 | 默认从钉钉进入，不要求员工记忆新网址或重复登录。 |
| 知识可信 | 所有正式知识必须有负责人、审核状态、适用范围、更新时间和版本记录。 |
| 移动可用 | 关键步骤在手机端可阅读、可放大、可逐步执行。 |
| 闭环可扩展 | V1.1A 只做统一服务入口跳转，但预留工单、AI、资产等模块扩展接口。 |
| 最小权限 | 钉钉可见范围与平台 RBAC 同时生效，敏感知识不得仅依赖入口隐藏。 |

# 3. 产品目标、成功指标与版本范围

## 3.1 V1.1A 产品目标

1. 员工可从钉钉工作台一键进入知识库，正常情况下不再输入独立账号密码。

2. 员工可通过关键词、分类和标签快速找到经过审核的 IT 故障答案与操作指南。

3. 知识编辑、审核、发布、复审、下架和版本追溯形成完整内容生命周期。

4. 员工在 PC 和手机端均可完成搜索、阅读、反馈和服务跳转。

5. 知识无法解决时，可从当前上下文跳转到现有钉钉 IT 服务表单，形成“先知识、后服务”的闭环。

6. 系统具备清晰的数据、权限和接口边界，为 V2.0 基于已审核知识的检索增强问答与后续 ITSM 集成预留扩展能力。

# 4. 用户、角色与核心场景

## 4.1 用户角色

| 角色 | 主要职责 | 典型权限 |
| --- | --- | --- |
| 普通员工 | 搜索、阅读并反馈知识；必要时发起 IT 服务申请。 | 查看本人可见知识、收藏、反馈、服务跳转。 |
| 知识编辑员 | 创建、维护和提交知识。 | 草稿管理、编辑本人或授权空间内容、查看反馈。 |
| 知识审核员 | 校验准确性、安全性、适用范围和表达质量。 | 审核、驳回、批准发布、发起复审。 |
| 知识库管理员 | 维护分类、空间、标签、模板、角色和运营配置。 | 全局配置、授权、下架、归档、统计。 |
| 系统集成管理员 | 维护钉钉应用配置、凭证、回调和同步任务。 | 集成配置、日志查看、故障处理；默认不具备内容审批权。 |

## 4.2 权限设计原则

钉钉应用可使用范围决定“谁能看到和打开入口”；平台 RBAC 决定“进入后能看什么、做什么”。

用户必须同时满足钉钉组织身份有效、应用可见范围有效、平台账号状态有效三个条件。

权限拆为两类，名称不得混用：

- **系统操作角色**：普通员工、知识编辑员、知识审核员、知识库管理员、系统集成管理员，用于决定用户可以执行什么操作。
- **内容受众范围**：全员、指定部门、指定用户组、指定用户、仅 IT，用于决定用户可以看到哪些知识。

最终访问条件为：组织身份有效且处于应用可使用范围内，平台账号未禁用，系统操作权限允许访问目标页面，并且用户命中知识的内容受众范围。显式禁用和显式拒绝优先于权限并集。

多部门员工命中任一允许部门即可访问；部门调动后以最新同步结果为准；临时系统角色必须设置生效和失效时间。内容受众不使用“指定角色”表述，避免与系统操作角色混淆。

内容编辑权、审核权和发布权原则上分离；紧急公告可设置管理员特批流程，但必须保留审计记录。

作者默认不能审核自己提交的知识；确需例外时必须由知识库管理员按受控流程临时授权，并记录原因、有效期和审计日志。

系统集成配置与知识内容管理分权，避免持有钉钉凭证的人员自动获得所有内容权限。

## 4.3 核心用户场景

| 编号 | 场景 | 说明 |
| --- | --- | --- |
| UC-01 | 员工自助排障 | 员工从钉钉进入，搜索“打印机离线”，阅读步骤并反馈已解决。 |
| UC-02 | 知识未解决 | 员工阅读后选择“未解决”，带着关键词、文章编号和问题分类跳转 IT 服务表单。 |
| UC-03 | 新员工快速上手 | 员工通过“新员工指南”查看账号、网络、打印、常用软件等入职知识。 |
| UC-04 | 编辑提交知识 | IT 编辑员根据标准模板编写故障处理知识，提交审核。 |
| UC-05 | 审核与通知 | 审核员收到钉钉提醒，审核通过后作者收到结果通知，知识上线。 |
| UC-06 | 到期复审 | 系统在知识到期前提醒负责人，复审后延长有效期或下架。 |
| UC-07 | 移动现场操作 | 员工在电脑不可用时，使用手机钉钉查看网络或终端故障处理步骤。 |

## 4.4 员工主流程

1. 打开钉钉工作台并进入“IT 知识库”。

2. 系统完成免登与权限判断，进入适配当前终端的首页。

3. 输入问题关键词，或按“账号 / 软件 / 网络 / 设备 / 企业系统 / 新员工指南”浏览。

4. 查看知识详情，按步骤执行并反馈“已解决 / 未解决”。

5. 若未解决，点击“提交 IT 服务申请”，跳转至现有钉钉表单。

# 5. 信息架构与知识体系

## 5.1 五维知识模型

V1.1A 将原先混在一起的“业务分类、文章类型、内容受众范围”拆分管理，避免把“运维案例库、SOP”与“网络、软件、账号”等业务主题并列。

| 维度 | 作用 | 示例 |
| --- | --- | --- |
| 知识空间 | 决定内容所属人群与管理边界 | 员工知识空间、IT 内部知识空间、管理员空间 |
| 业务分类 | 决定问题属于哪个 IT 主题 | 账号与权限、软件、网络、终端设备、企业系统、新员工指南 |
| 文章类型 | 决定内容表达模板与用途 | 故障处理、操作指南、SOP、运维案例、通知公告、FAQ |
| 标签 | 补充搜索与多维筛选 | Windows 10、VPN、打印机、钉钉、紧急 |

## 7.2 钉钉内交互规则

钉钉内打开时不展示独立登录页；免登处理中使用轻量加载状态，不闪现登录表单。

页面顶部避免重复展示与钉钉导航冲突的重型导航栏；保留清晰的返回和关闭逻辑。

文章直达链接在钉钉内打开时先完成免登，再恢复到目标文章；无权限时不得泄露标题或摘要。

外链、附件和 OA / 表单跳转需明确目标；失败时不得出现空白页。

移动端底部操作区固定展示“已解决 / 未解决”和“提交 IT 服务申请”，但不得遮挡正文。

## 7.4 易用性要求

搜索框示例应使用员工常见说法，如“电脑连不上 Wi-Fi”“忘记 ERP 密码”。

错误提示说明发生了什么、用户可以做什么、仍无法解决时联系谁。

每一步使用动作动词开头；风险操作必须先提示备份或影响范围。

按钮文案使用结果导向语言，如“提交审核”“打开 IT 服务申请”，避免“确定”“处理”等模糊词。

重要截图必须配文字说明，不能仅依赖颜色或图片表达。

## 8.4 数据关系说明

一个部门可包含子部门与多个用户；用户可归属多个部门。一个用户可拥有多个角色；一个角色可包含多个权限点，用户角色关系记录授权范围与有效期。

一个知识空间包含多个分类和文章；分类支持父子层级。

一篇知识拥有多个版本，但最多只有一个当前发布版本；同时可以存在一个草稿或待审版本。文章主状态与版本状态必须独立存储。

一篇知识可关联多个标签、审核记录、反馈、收藏、搜索点击和服务跳转记录。

钉钉用户映射与平台用户一对一或按企业隔离的一对多关系由技术方案确认。通知日志、同步日志、系统配置版本和审计日志必须与业务对象建立可追踪关联。

# 9. 业务规则与状态模型

## 9.1 文章主状态

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 正常 `active` | 文章主记录有效；是否对员工展示取决于当前发布版本及受众权限 | 创建工作版本、阅读当前发布版本、复审、下架 |
| 已下架 `offline` | 因错误、风险或业务变化停止使用 | 不可搜索；历史链接显示下架说明；可创建修订版本 |
| 已归档 `archived` | 长期保留且不再使用 | 仅授权管理人员查看，用于审计和追溯 |

## 9.2 版本状态与流转规则

| 版本状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 草稿 `draft` | 编辑中 | 编辑、预览、软删除、提交审核 |
| 待审核 `in_review` | 已提交审核并冻结 | 非作者审核员通过或驳回 |
| 已驳回 `rejected` | 审核未通过 | 作者基于该版本继续修改并重新提交 |
| 已发布 `published` | 当前线上版本 | 阅读、反馈、创建后继工作版本 |
| 已替代 `superseded` | 曾发布但已被新版本替代 | 仅授权查看与审计 |

1. 草稿 → 待审核：编辑员提交，必须填写版本说明、负责人、内容受众范围和复审日期。

2. 待审核 → 已发布：审核通过；将该版本设为 `current_published_version_id`，原发布版本转为“已替代”。

3. 待审核 → 已驳回：审核员必须填写意见；作者继续修改时创建或恢复为草稿。

4. 已发布版本 → 新草稿版本：线上版本继续可见，文章主状态仍为“正常”，直到新版本审核通过。

5. 复审到期不等同于内容失效。超过 `review_due_at` 后标记“复审逾期”并提醒负责人；低风险知识可继续展示但显示维护提示，高风险知识按配置自动下架。复审结论可以是继续有效、修订后发布或立即下架。

6. 正常 → 已下架：管理员或授权审核员执行，必须填写原因。

7. 已下架 → 已归档：确认不再恢复后归档；需要恢复时重新创建待审版本。

## 9.3 搜索与权限规则

搜索索引可以保存不同受众范围的已发布版本，但每次检索必须在服务端执行内容受众过滤。未授权内容不得返回标题、摘要、数量、附件名、高亮片段或联想词。

已下架和已归档内容不进入员工搜索。复审逾期内容是否继续展示按风险等级和空间策略处理，不再统一视为失效。

文章标题、摘要、附件名称同样属于权限保护对象，无权限时不返回任何内容。

搜索日志中若包含账号、手机号、IP 等潜在敏感信息，应按安全策略脱敏或缩短保留期。

## 9.4 反馈处理规则

| 反馈类型 | 系统处理 | 运营动作 |
| --- | --- | --- |
| 已解决 / 有帮助 | 计入正向反馈和排序信号。 | 定期识别高价值知识。 |
| 未解决 | 展示服务入口，并允许选择原因。 | 按月分析知识缺口和步骤问题。 |
| 内容错误 | 标记高优先级，通知负责人和审核员。 | 必要时紧急下架。 |
| 内容过期 | 记录当前版本与用户环境。 | 进入复审队列。 |
| 看不懂 | 记录步骤或段落位置（若可用）。 | 优化用语、截图和步骤拆分。 |

# 10. 钉钉集成与技术架构

## 10.1 总体架构

| 架构边界  知识库不部署在钉钉服务器中。钉钉提供工作台入口、免登授权码、组织身份与消息通道；知识库前端、后端、数据库、搜索索引、附件与日志仍部署在公司控制的基础设施中。 |
| --- |

| 层级 | 组成 |
| --- | --- |
| 访问层 | 钉钉 PC / 移动工作台、受控外部浏览器入口 |
| 前端层 | 响应式 Web 前端、钉钉 JSAPI 适配、错误与降级页面 |
| 业务层 | 认证会话、知识、搜索、审核、权限、通知、统计、服务跳转 |
| 集成层 | 钉钉免登、通讯录 / 用户同步、工作通知、统一 IT 服务入口与 `01_ServiceRequest` |
| 数据层 | 关系数据库、搜索索引、对象存储、缓存、审计与业务日志 |
| 运维层 | 监控告警、备份恢复、配置与密钥管理、发布与回滚 |

## 10.2 免登流程

1. 员工在钉钉工作台点击“IT 知识库”。

2. H5 前端确认运行环境，并调用钉钉端内免登能力获取短期授权码。

3. 前端仅将授权码和必要的防重放参数提交给知识库后端。

4. 后端使用受保护的应用凭证调用钉钉服务端接口，换取可信用户身份。

5. 服务端按返回的 `corpId + userId` 查找或创建平台用户映射；如接口返回 `unionId`，仅将其用于跨应用关联或补充映射，并同步必要的姓名和部门信息。

6. 后端执行组织状态、应用范围和平台账号状态校验，创建平台会话。

7. 前端进入原目标页面；失败时展示明确错误和重试 / 求助入口。

## 10.3 安全边界

AppSecret、访问令牌等钉钉凭证只保存在服务端密钥系统，禁止写入前端代码、日志或配置仓库。

免登授权码应短期、一次性使用；后端校验请求来源、会话状态和防重放参数。

前端传来的姓名、工号、部门、角色不作为授权依据。

所有文章、附件、搜索和后台接口都执行服务端权限校验。

钉钉身份同步失败时采用“安全失败”策略：不扩大权限；超过允许时效后限制访问并提示管理员。

通知内容不直接包含密码、密钥、服务器配置或其他敏感信息，点击后再在授权页面查看。

## 10.4 应用配置要求

| 配置项 | 要求 |
| --- | --- |
| 应用类型 | 企业内部 H5 微应用 |
| 移动端首页地址 | 正式 HTTPS 地址；与免登 JSAPI 使用域名保持一致 |
| PC 端首页地址 | 正式 HTTPS 地址；支持 PC 钉钉工作台打开 |
| 可使用范围 | 按公司组织策略配置，建议先试点部门后逐步放开 |
| 权限申请 | 只申请免登、必要通讯录字段与工作通知等最小权限 |
| 回调 / 可信域名 | 按钉钉要求配置；区分测试与生产环境 |
| 出口 IP | 如接口要求白名单，使用固定且受控的服务器出口 IP |
| 应用凭证 | 分环境保存、定期轮换、最小可见、禁止共享 |

## 10.5 用户同步策略

| 方式 | 触发 | 用途 | 建议 |
| --- | --- | --- | --- |
| 登录时按需同步 | 用户每次或定期登录 | 确保当前用户基本信息及时 | P0 |
| 定时增量同步 | 定时任务 | 更新部门、姓名和状态 | P1 |
| 事件回调同步 | 组织变更事件 | 快速处理入离职与部门变化 | 视权限与稳定性评估 |
| 管理员手动同步 | 排障或紧急处理 | 单人 / 部门重试 | P1 |

## 10.6 通知集成策略

V1.1A 优先采用企业内部应用工作通知，消息点击跳转至具体知识或审核页面。

通知服务应封装统一模板、接收范围、幂等键、重试、频控和发送日志。

重要公告需进行权限和目标范围校验，不把“应用可见范围”等同于“公告接收范围”。

钉钉接口异常时，业务操作本身应可完成；通知进入重试队列并在后台提示。

## 10.7 IT 服务入口集成

V1.1A 唯一跳转目标为现有“IT 服务自助提报单”，提交数据最终进入 `01_ServiceRequest`。知识库不直接维护多套 OA / 多维表入口，也不在本期承诺表单提交状态回写。

| 知识库上下文 | `01_ServiceRequest` 目标字段 | V1.1A 处理规则 |
| --- | --- | --- |
| `source_channel` | 来源渠道 | 固定为 `knowledge_base` |
| `kb_no` | 来源知识编号 | 携带当前知识编号；零结果场景为空 |
| `category_code` | 服务类别 | 按知识分类映射，用户可在表单中修正 |
| `search_session_id` | 来源搜索会话 | 仅后台统计使用，不向员工展示 |
| `client_type` | 提报终端 | 自动识别 PC / iOS / Android |
| 问题描述摘要 | 故障描述 | 无法安全预填时生成可复制文本 |

完整搜索词、问题描述和个人信息不得直接放入 URL。优先传递一次性、短时有效的 `context_token`，由受信后端读取最小必要上下文；若现有表单不支持该方式，则只携带非敏感编号并提供复制文本。字段映射、枚举转换、Token 有效期及失败处理须在独立《知识库—IT 服务入口字段映射表》中定稿。

## 10.8 异常与降级

| 异常 | 处理原则 |
| --- | --- |
| 未在钉钉内打开 | 提示从钉钉工作台进入；按安全策略提供备用登录或联系 IT。 |
| 免登授权码获取失败 | 允许重试，展示错误编号；不接受用户手工输入身份绕过。 |
| 钉钉服务端接口超时 | 短次数重试；不扩大权限；记录链路并告警。 |
| 用户不在可使用范围 | 提示无权限并给出申请渠道，不显示任何知识内容。 |
| 离职 / 禁用用户 | 终止新会话；已存在会话按安全策略撤销。 |
| 通知发送失败 | 业务操作继续完成；通知进入重试，超过阈值告警。 |
| OA / 表单跳转失败 | 提供备用入口、复制链接和联系 IT 方式。 |
| 搜索服务不可用 | 展示分类和热门知识缓存；提示服务暂时异常。 |

## 11.2 可用性与恢复

建议月度可用性目标不低于 99.5%，计划维护窗口除外。

核心服务具备健康检查、错误率、响应时间、免登失败率和通知积压监控。

数据库每日备份；建议 RPO ≤ 24 小时、RTO ≤ 4 小时，最终值由公司基础设施能力确认。

上线和数据库变更必须具备回滚方案；搜索索引可从主数据重建。

## 11.3 安全与合规

| 领域 | 要求 |
| --- | --- |
| 传输 | 所有正式环境访问使用 HTTPS；内部接口也应使用受控网络和鉴权。 |
| 凭证 | 集中保存、分环境、定期轮换、最小权限；禁止进入代码、前端和普通日志。 |
| 授权 | 服务端 RBAC + 数据范围校验；附件与搜索同样受控。 |
| 审计 | 记录登录、授权、发布、下架、配置、导出和集成管理操作。 |
| 隐私 | 只采集实现业务所需的员工字段；明确保留期限和删除 / 匿名化策略。 |
| 内容安全 | IT 内部 SOP、服务器配置、账号处理流程不得默认向全员开放。 |
| 日志 | 对令牌、授权码、手机号、邮箱、IP 和搜索敏感词执行脱敏与访问控制。 |
| 文件安全 | 限制白名单格式和单文件大小；上传后隔离扫描；拒绝可执行文件和双扩展名风险文件；附件下载必须鉴权、记录审计并按保留期清理。 |

## 11.4 兼容性与可访问性

兼容性以发布前核验的钉钉官方要求和公司实际客户端为准，不再使用模糊的“支持主版本”。开发前建立并批准兼容矩阵，至少包含：Windows 钉钉最低版本、iOS 钉钉最低版本、Android 钉钉最低版本、操作系统版本、免登 JSAPI、返回导航、附件打开和服务入口跳转。

当前设计参考值：Android / iOS 钉钉 7.0.45 及以上，Windows / macOS 钉钉 7.0.50 及以上；正式开发和每次发布前必须重新核验官方文档，不满足最低版本时展示升级提示。

支持主流 Windows 10 / 11 分辨率与 iOS / Android 常见屏幕。

正文最小可读字号、触控目标、颜色对比、键盘导航和焦点状态满足内部可访问性要求。

截图配文字说明；颜色不是唯一信息载体；错误信息可由屏幕阅读器识别。

## 11.5 可维护性与扩展性

知识、搜索、认证、通知、统计和 ITSM 集成保持清晰模块边界。

钉钉相关能力通过集成适配层封装，避免业务代码依赖具体接口细节。

文章正文采用可迁移的结构化格式；附件与正文关联可批量导出。

为 V2.0 检索增强问答预留文章版本、段落、引用来源、内容受众范围和内容有效性字段；V1.1A 不生成答案。

为 ITSM 深度联动预留外部工单编号、来源上下文和状态回调扩展点，但 V1.1A 不启用。

# 14. 上线与运营方案

## 14.1 上线步骤

1. 需求与原型评审：确认 V1.1A 范围、页面、字段、角色、验收和待确认项。

2. 环境准备：完成域名、HTTPS、服务器、数据库、搜索、对象存储、监控和备份。

3. 钉钉测试应用：配置测试地址、最小权限与试点可使用范围，验证免登和通知。

4. 首批知识建设：优先覆盖高频故障、新员工场景和现有 ITSM 常见服务。

5. 集成与系统测试：完成端到端、权限、兼容性、安全、性能与恢复测试。

6. 试点上线：选择 IT 团队及一个或两个业务部门，收集搜索和反馈数据。

7. 正式发布：扩大钉钉应用范围，发布使用指南和反馈渠道。

8. 运营复盘：上线后第 1、2、4 周复盘零结果词、未解决知识、免登错误和服务跳转。

### 14.1.1 Go / No-Go 与回滚条件

满足以下条件方可正式放量（Go）：所有 P0 用例通过；无未关闭的高危安全问题；备份恢复和回滚演练通过；统一服务入口及 `01_ServiceRequest` 映射验证通过；兼容矩阵通过；首批 30—50 篇知识已审核发布且均有负责人和复审日期；监控、告警和值班责任人已就绪。

出现任一情况必须暂停上线或回滚（No-Go）：身份或权限越权；附件可被未授权访问；P0 数据丢失或错误覆盖；端到端进入成功率持续低于 95%；统一服务入口大面积无法打开；核心页面 P95 连续 15 分钟超过目标两倍且无法快速恢复。

试点结束标准：连续两周无 P0 事故；端到端进入成功率、零结果率和服务入口打开成功率达到目标或有批准的整改计划；试点部门完成验收签字；首批高频问题无重大知识缺口。

# 附录 A：需求优先级

| 级别 | 定义 | 发布原则 |
| --- | --- | --- |
| P0 | 核心链路、权限、安全、数据正确性或上线必要能力 | 未完成或未通过验收不得正式上线 |
| P1 | 显著提升核心试点体验、运营与维护效率的能力 | 可经评审纳入 V1.1A 或顺延至 V1.1B |

# 附录 B：术语表

| 术语 | 说明 |
| --- | --- |
| PRD | Product Requirements Document，产品需求文档。 |
| H5 微应用 | 在钉钉工作台中打开的网页应用，实际业务系统可部署在企业自有基础设施中。 |
| 免登 | 员工在钉钉内进入应用时，通过授权码换取可信身份，无需再次输入账号密码。 |
| corpId | 钉钉企业组织标识。 |
| userId | 员工在特定钉钉企业内部应用中的用户标识，与 `corpId` 组合用于平台用户主要映射。 |
| unionId | 用于跨应用身份关联或补充映射的人员标识，不是所有场景下唯一必选的主键。 |
| RBAC | Role-Based Access Control，基于角色的访问控制。 |
| 知识空间 | 用于区分员工知识、IT 内部知识等管理与可见边界。 |
| RPO | 可接受的数据恢复点目标。 |
| RTO | 服务从故障到恢复的目标时间。 |
